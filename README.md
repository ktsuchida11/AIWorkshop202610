## 一本道(第3回「育てる」パートの筋)

**第2回の宿題からスタートし、「失敗分解 → 分布ギャップ仮説 → 合成で埋める → 再実測」を一本道で見せる。**

1. **第2回の到達点と宿題**: ゲート通過94%はゲート(守り)込みの数字。ローカル素通過は60%で、
   **35%はSonnetの再生成(=クラウド費用+レイテンシ+50s)に頼っている**。この35%を削るのが「育てる」。
2. **失敗分解(8/9実測)**: タグなし17件中、**13件は同じ検索結果でSonnetならタグ付きで書けた**
   (=検索のせいではない)。うち10件はv2も557〜1216字の長文を書いているのに**タグだけ落とす=規律の緩み**。
   残り4件はSonnetもタグなし=材料不足の正しいお断り(モデルでは救えない)。
3. **分布ギャップ仮説**: 蒸留データのチャンクは合成でキレイ——**質問にドンピシャ関連する材料しか見たことがない**。
   実DBの検索結果は類似度順の「**斜め関連**」——質問に部分的にしか関係ないチャンクが混ざる。
   学習分布に無い入力(ノイズ混じりの材料)を見ると、8Bは規律(出典タグ)から先に崩れる。
   ※「合成heldout満点(gate 1.000)≠実環境(素通過60%)」のギャップそのものの説明でもある。
4. **v3=合成で埋める**: シナリオ生成に「斜め関連チャンク」を混ぜ、**ノイズ混じりの材料でも
   関連チャンクだけに出典タグを付けて書き切る**教師答案を学習させる。
5. **再実測**: 同じ48ケース(C構成)で素通過60%→**目標90%圏**・エスカレ率35%→10%圏。
   ゲートは残す(守りと攻めの併用・揺らぎ±10%の吸収装置)。

> 語りの核: **「守り(ゲート)は失敗をコストに転化する装置。育てる(v3)は失敗そのものを減らす。」**
> 第1回=能力を注入、v2=挙動を整形、v3=**分布を寄せる**——SFT改善の3類型が3回で出揃う。

## v3 設計(実装方針)

### 変えないもの(重要)

- **学習時 system は v2 と一字一句同一**(`_ANSWER_SYSTEM_V2`)。変えるのは入力分布(チャンク側)だけ。
  → 配信時に market-report-chat 側のプロンプト同期が**不要**(アダプタ/GGUF差し替えのみ)。
  v2で作った動的基準日ルート(`qwen3-gen-v2`)がそのまま使える=分布外事故の再発防止。
- 教師(claude-sonnet-5)・自己検査ゲート(`gate_passed`)・逐次書き込み+途中再開・v2の
  鮮度/thin/基準日サンプリングも全て維持(v3はv2の上位互換データ)。

### 加えるもの

- **斜め関連チャンク指示**: シナリオ生成プロンプトに「chunks のうち N 件(1〜2件)は、質問には直接
  答えないが検索でヒットしそうな内容(同セクターの別トピック/隣接セクターの言及/時期ズレの話題)に
  すること。残りのチャンクだけで質問に答えられること」を追加。
- **抽選**: `diagonal_fraction`(初期値 0.5)で v3 シナリオの半分にノイズを混入。thin(薄材料)との
  併用可 = 「関連1チャンク+ノイズ1〜2件」——**実測弱点(retrieved:1で規律が緩む)の再現形**。
- **レコード拡張**: `diagonal`(bool)/`n_noise` を保存 → 評価スライス(diagonal サンプルのタグ付与率・
  ゲート通過率)を v2_slices 系に追加。教師 gold 基準値も天井測定で先行取得。

### 工程(v2 と同じ関門・費用感)

| 関門 | 内容 | 費用 | 状態 |
|---|---|---|---|
| 1 | 実装+テスト(`make test` グリーン・dry-run) | $0 | **完了(8/10・PR #57)** |
| 2 | スモーク 5ケース(斜め関連チャンクの生成品質を目視) | ~$0.3 | **合格(8/10・全 gate 通過・ノイズ品質良)** |
| 3 | 教師天井の再測定(30×3・v3 分布) | ~$4 | **合格(8/10・gate 1.000/ng 0.991・`reports/gen_labels_v3.md`)** |

### リスク・留保(正直に言う)

- 素通過60%は点推定(ラン間±10%の揺らぎ実測済み)。C6 は複数ラン or ゲート併用前提で評価する。
- 斜め関連ノイズの「質」は合成頼み——実DBチャンクの分布に完全には寄らない(実データ蒸留は
  コンプラOK後の本命)。第3回では「合成でどこまで寄せられたか」を実測で正直に示す。
- タグなし4件(Sonnetもお断り)はv3でも残る=100%は狙わない。ゲートの不合格3件が「正しいお断り」
  だったのと同じ構図。

## スライド素材(第3回「育てる」パート・5〜6枚想定)

- **V1 — 第2回の宿題**: 94%の内訳バー(素通過60% + エスカレ救済34% + 正しいお断り6%)。
  「35%はSonnet頼み=費用とレイテンシ。ここを削る」
- **V2 — 失敗分解**: タグなし17件の分解表(13件=Sonnetなら書けた/うち10件=長文なのにタグ落ち/
  4件=材料不足)。「検索のせいでもモデル能力のせいでもなく、**規律が緩む条件**がある」
- **V3 — 分布ギャップ仮説**: 蒸留チャンク(ドンピシャ)vs 実DBチャンク(斜め関連)の実例対比。
  「合成heldout満点が実環境で60%に落ちる理由はここ」
- **V4 — v3設計**: 斜め関連チャンクを合成で混ぜる図(system不変・入力分布だけ寄せる)。
  SFT改善3類型(能力注入/挙動整形/**分布を寄せる**)
- **V5 — 実測(2026-08-13 記入)**: 素通過 3ラン表 = **C4(v2×vec) 60% / C7'(v3×vec) 58% /
  C6(v3×hybrid) 56%**——検索入力完全一致47ケースで 28vs28 の同点 = **90%圏は未達**。
  効いた部分 = 期間ミスマッチ検出(edge_case 0/5→2/5・EC-04「2025年1月の記載はない」と明示+
  調査チャンクにタグ=diagonal 蒸留の狙いが実環境で発現)。作話は横ばい(増えていない)。
  残った弱点 = **広域ダイジェスト質問(「今週の概況は？」「気になることある？」)でタグ全落ち**
  (同一チャンク再生成で本文確認: 911〜1320字のフル回答にタグ0個。PT-06 は再現時にタグ5個=
  同一入力でも揺れる)。
  語り: 「**仮説(斜めチャンク)は部分的に正しかったが、本丸は質問型の分布だった**。
  合成満点→実環境58%の乖離が v2 に続き v3 でも再現 = 測るたびに次のギャップが見える。
  だから品質保証はゲート(レバーA 94%)が本命で、モデル改善は積み上げ。
  次の仮説 = 蒸留 v4 にダイジェスト質問型(複数チャンク要約+段落毎タグ)を足す」。
  測定の落とし穴2つも正直に共有: .env の HYBRID_SEARCH 暗黙適用で C6 が合算測定になっていた
  (retrieved_ids 全件比較の RRF 指紋で検出→C7' 追加で分解)・Mac Ollama 停止時の
  Sonnet silent fallback(served model 事前確認を手順化)。
- **V6 — レバーC(実装・実測済み 2026-08-12)**: ハイブリッド検索(pg_trgm キーワード検索を
  RRF でベクトル検索に統合・既定OFF・market-report-chat #321→PR #322 マージ済み)。
  「retrieved:1 で緩む」のもう半分=検索側への手当て。
  **A/B 実測(48ケース・検索のみ評価): Recall@3 53.7→56.0% / @5 58.7→63.4% / @8 62.8→65.1%・
  MRA's Eye コラム系 25→50%(字面一致が効く典型)・劣化カテゴリなし**。
  語り: 「embedding は意味で拾い、キーワードは字面で拾う——相補的な取りこぼしを RRF で束ねる。
  レバーB(モデル=分布を寄せる)とC(検索=材料を良くする)の合わせ技で C6 を測る」。
  リランカー(cross-encoder)は新モデル基盤が要るため見送りと正直に言う
